# Data Layer

The pages use one set of functions in `src/lib/mock/cases.mock.ts`.

## Two modes

### Mock mode (default)

The app uses the sample cases already included in the project. This lets the frontend run without the backend.

### Backend mode

Set these values in a local `.env` file:

```env
VITE_DATA_SOURCE=backend
VITE_API_BASE_URL=http://localhost:8000
```

The frontend then talks to the current FastAPI endpoints.

## Current backend connection

### Create a case

Frontend function: `submitCase(address, chain, notes)`

Backend request:

```text
POST /cases
{
  "case_id": "generated by frontend",
  "wallet_address": "frontend address",
  "chain": "TRON",
  "status": "In Progress"
}
```

The backend currently does not store the optional `notes` field, so the frontend keeps that field in the form but does not pretend it was saved by the backend.

### List cases

```text
GET /cases
```

The backend returns `wallet_address`; the frontend converts it back to its existing `address` field so the current UI does not need to be rewritten.

### Open one case

The current backend does not provide `GET /cases/{case_id}`. The frontend therefore calls `GET /cases` and selects the requested case by `case_id`.

### Get transfers

```text
GET /cases/{case_id}/transfers
```

Available through `fetchCaseTransfers()` for the investigation UI.

### Run the full trace

```text
POST /cases/{case_id}/trace
```

Available through `runCaseTrace()` for the investigation UI.

## Important current limitation

`submitted_at` is not part of the current backend `Case` response. For cases submitted from this browser, the frontend remembers the submission time locally so the existing UI can still display it. Existing backend cases that were not submitted from this browser have no real submission time available and show an empty value until the backend contract is extended.
